# SmartCart Raspberry Pi 4 시연 운영 런북

Pi 4 · Ubuntu 22.04 ARM64 · ROS 2 Humble · C1 LiDAR · 단일 BU04 · BU03 태그

기본 순서는 **SSH 접속 → LiDAR·BU04 센싱 → 실제 조종 서버**다. 아래 Windows 명령은 PC PowerShell에서, 그 밖의 명령은 SSH 접속 후 Pi 터미널에서 실행한다.

## 실행 전 확인

**`real.sh`는 실제 GPIO 서버를 시작한다.** 센서 오류·ID 불일치·시간 초과 시 구동 잠금, 2초 PWM 응답 감시, 비상정지와 모터 전진 극성·정지 조건을 확인하기 전에는 실제 주행을 보류한다. PWM 표시는 바퀴 회전이나 물리 전원 차단의 증거가 아니다. 현재 비상정지의 Pi GPIO 피드백과 엔코더는 없다.

최근 Pi 센서 조회에서 LiDAR 720개 중 무효 빔 77~80개가 관측됐다. 전방 미관측 영역과 센서 이상 시 정지·재활성화 동작을 검수해야 한다. 현재 Pi의 추종 코드 일부는 추출 ZIP 및 GitHub 검토본과 달라 안전 잠금 적용 여부가 확인되지 않았다. **이 검수가 끝나기 전에는 아래 실제 서버 실행도 보류한다.**

GitHub `main`의 `pi-runtime/pi-field-snapshot/`은 GPIO를 잠근 검토본이며 Pi에 자동 적용되지 않는다. 시험용 설정을 실제 설정으로 복사하거나 안전 잠금을 우회하지 않는다. 장치 설정 변경 전 BU03/BU04 AT 백업을 보존한다.

## 1. SSH 접속 — Windows PowerShell

현재 Pi 주소가 `192.168.43.212`인 경우:

```powershell
ssh capstone@192.168.43.212
```

접속 후 `capstone@SUDO:~$`처럼 Pi 프롬프트가 표시되는지 확인한다. 주소가 바뀌었다면 Pi에서 `hostname -I`로 확인한 현재 주소를 사용한다.

## 2. 센싱 — Pi 터미널

LiDAR와 BU04를 Pi에 연결하고 BU03의 전원을 켠다. 센싱이 이미 실행 중인지 확인한다.

```bash
curl -fsS --max-time 2 http://127.0.0.1:8765/api/health | python3 -m json.tool
```

응답이 오면 중복 시작하지 않는다. HTTP 응답이나 `lidar_valid`만으로 모든 방향의 빔과 실제 장애물 정지가 검증되는 것은 아니다. BU04 측정 유효·ID 일치, LiDAR 갱신·무효 빔 및 장착 방향을 확인한다.

응답이 없으면 먼저 포트와 잠금 보유자를 확인한다.

```bash
ss -ltnp '( sport = :8765 )'
fuser -v /tmp/smartcart-runner-*/live.lock /tmp/smartcart-runner-*/8765.lock
```

기존 센싱 실행기와 잠금 보유자가 없을 때만 다음을 실행한다.

```bash
cd "$HOME/smartcart"
bash sensors.sh
```

`sensors.sh`는 추출본 기준으로 기존 센싱을 확인하고 없을 때 단일 BU04 센싱을 시작한다. Pi의 현재 파일이 동일한지는 별도 확인이 필요하다. 터미널을 열어 두며 기존 수집기와 중복 실행하지 않는다. 잠금 오류가 나면 소유 프로세스를 확인하고 잠금 파일을 임의로 삭제하지 않는다.

## 3. 실제 조종 서버 — Pi 터미널

사용자는 Pi에서 `bash real.sh`로 서버를 실행하고 `https://192.168.43.212:8081/`에 접속할 수 있다고 보고했다. 화면 연결만으로 실제 주행의 안전성을 확인할 수는 없다.

**위 안전 검수가 완료된 경우에만**, 별도 SSH 터미널에서 기존 조종 서버가 없는지 확인한 뒤 실행한다. 현재는 검수 전이므로 실행을 보류한다.

```bash
ss -ltnp '( sport = :8081 )'
```

8081이 사용 중이지 않고 안전 검수가 완료된 경우 실행한다.

```bash
cd "$HOME/smartcart"
bash real.sh
```

8081이 사용 중이면 서버를 중복 실행하지 않는다. 서버가 출력한 현재 HTTPS 주소·접속키를 확인하고 같은 핫스팟의 PC나 휴대폰에서 접속한다. 인증서가 현재 IP에 맞는지 확인하고 TLS 경고를 우회하지 않는다. 접속키와 개인키는 공유하지 않는다.

추출 당시 `virtual.sh`도 기본 GPIO를 선택했다. 이름만 보고 가상 출력으로 판단하지 않는다.

## 종료와 오류

- 조종 중 정지가 필요하면 비상정지 수단을 사용한다. 직접 시작한 서버는 해당 터미널에서 `Ctrl+C`로 종료하고, 센싱도 직접 시작했다면 해당 터미널에서 별도로 종료한다.
- 센서 이상, 무효·미관측 빔, 2초 응답 미확인 또는 비상정지 이상 시 구동을 중단하고 모터 전원을 차단한다.
- Pi의 장치 설정·센서 보정·모터 배선은 이 런북 갱신으로 변경되지 않는다.
