# Pi 현장 소스 스냅샷 — 검토 전용

2026-11-24 사용자가 Pi의 `~/smartcart`에서 추출한 소스 중 실행 경로와 관련된 파일 396개를 원본 내용 그대로 보존했다. 기존 `pi-runtime/`과 `pi-export-reference/`를 덮어쓰지 않는다. 이 폴더는 설치본이나 실행 허가된 버전이 아니다.

- `real.sh`와 `virtual.sh`는 모두 기본적으로 `gpio` 백엔드의 `releases/real-uwb-v1/server.py`를 가리킨다. 이름만으로 가상 출력이라고 판단하면 안 된다.
- `sensors.sh`는 `SmartCart-D5-v2/smartcart`의 단일 BU04 실측 센싱 실행기를 가리킨다. 실제 가동 프로세스나 현재 장착 설정은 이 스냅샷만으로 확인하지 못했다.
- 실차 서버는 `SmartCart_ManualDrive_180/smartcart`의 모터 코드와 `smartcart-virtual-4digit.DlQ3Pf7U`의 로그인 코드를 참조하며 UWB 추종과 LiDAR 처리 코드를 포함한다. ROS 워크스페이스 소스도 보관했다.
- 과거 백업·실험·중복 업데이트 폴더는 이 PR에 넣지 않았다. 원본 ZIP과 Pi 파일은 변경하지 않았다.
- 장치 설정, 장착·보정값, `follow_config.json`, `live_zone_modules/cart_geometry.json`, 인증서·키, 로그, 바이너리와 실측 기록은 추출 대상에서 제외됐다. 그 결과 이 스냅샷은 그대로 실행할 수 없고 Pi의 실제 설정이나 주행 상태를 재현할 수 없다.

## 확인 및 주의

- ZIP의 SHA-256과 압축 무결성을 확인했다. 소스 내 비밀 값에 대한 자동 탐색은 완전한 보안 검토를 대체하지 않는다.
- 원본 소스의 조이스틱 관련 Node 시험 두 개는 통과했다.
- 원본 추종 제어 시험 25개 중 2개는 기대값 불일치로 실패했고 10개는 제외된 `cart_geometry.json`이 없어 오류로 끝났다. 나머지 13개는 통과했다. 시험과 현재 코드의 불일치 원인은 확인이 필요하다.
- 현재 코드에는 센서 이상 시 출력을 정지하면서 무장 상태를 유지하는 경로가 있어, 복구 후 재출발과 재활성화 조건을 독립 검수해야 한다. 기존 관측기의 구동 승인 상태와 추종 제어의 관계도 검토해야 한다.
- `releases/real-uwb-v1/README.md`는 후속 코드와 다른 과거 설명을 포함할 수 있다. 실제 설정, LiDAR·UWB 분리 및 복구, 모터 극성, 비상정지 피드백, 2초 PWM 감시와 실차 제동은 검증되지 않았다.

Pi GPIO를 열거나 모터를 작동시키지 않았으며 센서 연결과 Ubuntu·ROS 빌드는 시험하지 않았다. 안전 조건을 검토하기 전 이 스냅샷을 Pi에 덮어쓰거나 실차 운행에 사용하지 않는다.
