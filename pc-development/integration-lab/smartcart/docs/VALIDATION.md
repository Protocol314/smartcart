## 브라우저 검사 방식과 한계

이 환경의 Chromium은 실제 localhost 주소로 이동할 때 `ERR_BLOCKED_BY_ADMINISTRATOR`를 반환했습니다. 해당 제한을 해제하지 않았습니다. 실제 HTML/CSS/JS를 격리 문서에 로드하고 EventSource 입력을 주입해 **실제 DOM·Canvas**를 검사했습니다. UI 미리보기는 이 실행 결과를 캡처한 것이며 이미지 생성 모델로 만든 목업이 아닙니다. 합성 테스트 데이터는 `DEMO / 합성 · 비실측`으로 표시됩니다.

브라우저의 다운로드 이동은 가로채어 파일명·Blob 내용을 검증했습니다. 실제 파일 다운로드 완료, 네이티브 localStorage 영속 저장, HTTP 또는 file:// 페이지의 브라우저 직접 로딩은 검증 완료로 취급하지 않습니다. 반면 Python 테스트에서는 네이티브 소켓을 통한 HTTP 정적 자산·SSE 1/2 Hz 전송을 별도로 확인했습니다. 이 두 검사를 합쳐 전체 브라우저 네트워크 경로를 검증했다고 주장하지 않습니다.

## 반응형 검사

다음 CSS viewport에서 수평 스크롤 넘침이 없고 레이더 캔버스가 정사각형으로 화면 안에 유지되는지 검사했습니다.

```text
320×568   360×800   390×844   414×896
768×1024  820×1180  844×390   1024×768
1280×800  1440×900  1920×1080
```

320 px 설정 창의 범위·내부 수평 overflow도 검사했습니다. 세로 공간이 부족한 화면에서는 세로 스크롤이 정상 동작 방식입니다. **실물 iPhone/Android/iPad/태블릿 Safari/모바일 Chrome 테스트를 대체하지 않습니다.** 해당 실물 테스트는 수행하지 않았습니다.

## 성능 관련 확인

웹 자산 전체는 무압축 58,688 bytes(약 57.3 KiB)입니다. UI 런타임 외부 네트워크 자산은 없습니다. 격자 캐시가 애니메이션 중 재생성되지 않고, 실측점 레이어는 프레임 갱신 때만 갱신되는지 검사했습니다. 회전선은 최대 30 FPS로 제한하며 실제 프레임 속도는 기기·브라우저에 따라 달라집니다. Raspberry Pi에서의 CPU/RAM 및 실물 센서부터 화면까지의 종단 지연은 측정하지 않았습니다.

## 재실행

```bash
bash scripts/test.sh
# 개발용 playwright + Chromium이 설치된 환경
python3 tests/browser_smoke.py --chromium /usr/bin/chromium --output validation-output
```

브라우저 테스트는 다운로드 이동을 가로채는 격리 테스트입니다. 실행 프로그램 자체에는 playwright·Node.js가 필요하지 않습니다.

## 현장 수락 확인

실제 모터 구동 없이, 다음을 확인한 뒤 주행 실험과 구분해 기록하십시오.

1. `/scan`이 기존 약 10 Hz로 유지되고 `SOURCE=ROS /scan`, `LIVE`, 실제 RX 수치가 일관적인지 확인합니다.
2. 전/좌/우의 알려진 표적으로 yaw·오프셋을 확인하고 벽 단면의 여러 측정점이 도트 라인을 이루는지 확인합니다.
3. 가까운 상자 뒤의 벽, 스캔이 끊긴 각도에서 윤곽선이 임의로 이어지지 않는지 확인합니다. 물체별 정확한 분리/분류는 보장하지 않습니다.
4. 드라이버 중단·서버 중단 시 점·윤곽·거리값이 숨겨지는지 확인합니다. 이 동작은 하드웨어 정지가 아닙니다.
5. 사용할 실물 휴대폰·태블릿에서 가로/세로 회전, 설정, 파일 저장을 확인합니다.

Raspberry Pi ROS/DDS/C1 연속 수신·실측 정확도·주행·PID·UWB 연동은 이번 제작 환경에서 시험하지 않았습니다.
