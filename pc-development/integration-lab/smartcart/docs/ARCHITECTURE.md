# 구조·처리 기준·향후 제어 연동

## 현재 구현

```text
sllidar_ros2 -> sensor_msgs/msg/LaserScan (/scan)
    -> rclpy read-only subscriber [Best Effort, Keep Last 5, Volatile]
    -> finite JSON normalisation + latest-value mailbox
    -> HTTP /api/frame and SSE /api/events?hz=1|2
    -> browser projection + Canvas 2D / Python ASCII client
```

ROS 수신 루프, 웹 전송 루프, 애니메이션 루프를 분리합니다. 센서가 실제로 10 Hz를 발행하면 입력은 그 주기로 처리하고, SSE는 설정된 1/2 Hz 시점에서 최신 메시지 하나를 선택합니다. 서로 다른 스캔의 거리값을 평균내거나 합치지 않습니다. UI 변경으로 LiDAR의 RPM, scan mode, ROS 발행 주기가 바뀌지 않습니다.

메시지는 Python 표준 라이브러리 HTTP 서버가 같은 출처의 정적 HTML·CSS·JavaScript와 함께 제공합니다. 별도 ROS bridge, 웹소켓 라이브러리, npm, pip 또는 CDN이 필요하지 않습니다. ROS 실측 모드는 기존 `rclpy`와 `sensor_msgs`에 의존합니다. 독립적인 정적 페이지에서는 실측이 아니라 오프라인 예제·파일 재생만 가능합니다.

브라우저는 매번 전체 페이지를 다시 로드하지 않습니다. SSE 데이터 갱신은 1/2 Hz이고 Canvas 회전선은 `requestAnimationFrame`으로 최대 30 FPS로 그립니다. 격자·스캔·회전선을 3개의 Canvas로 분리하며 격자는 크기/설정 변경 때만, 스캔은 프레임/상태 변경 때만 그립니다. 배율은 DPR 2 이하·레이어 한 변 1,600px 이하로 제한합니다. 숨겨진 탭에서는 애니메이션을 멈추고 reduced-motion 설정이면 회전선만 생략합니다. 회전선은 실제 C1 로터 각도와 동기화하지 않습니다. 새 프레임은 회전선이 해당 방향에 닿을 때까지 기다리지 않고 전체 점을 한 번에 바꿉니다.

## 데이터 해석

`theta_i=angle_min+i*angle_increment`를 사용합니다. 배열 앞 128개만 있는 경우도 128개를 360°에 다시 분배하지 않습니다. 실제 배열 길이가 예상과 다른 경우 경고하며, 빈 꼬리를 메우지 않습니다.

센서 정의의 `range_min`~`range_max` 안에 있는 유한 거리값만 렌더링합니다. Inf, NaN, null은 유효 반사점으로 보지 않습니다. 유효 센서 점에 고정 laser→cart 변환을 적용한 후 카트 중심 반경 5 m로 화면을 자릅니다. 센서 최대거리를 5 m로 바꾸지 않습니다.

백엔드는 정규화한 **전체 수신 배열**을 전달합니다. 표시 반경·yaw·오프셋·색상 임계값·윤곽 연결 상한은 브라우저별 설정이므로 한 사용자의 변경이 다른 사용자나 ROS 드라이버에 영향을 주지 않습니다. CLI 보정 설정은 CLI 인수로 별도로 전달합니다.

반환점의 색은 카트 중심 거리로만 정합니다. 기본값은 빨강 1 m 미만, 노랑 1 m 이상~3 m 미만, 초록 3 m 이상이며 설정에서 변경할 수 있습니다. 이 임계값은 시각적 구분이지 안전 등급 또는 제동 기준이 아닙니다. 객체 종류를 추론하지 않습니다.

## 실측점과 윤곽

각 유효 측정점을 원래 위치에 표시하고, 같은 스캔의 연속 인덱스만 보수적인 거리 조건으로 연결합니다. 평균 위치로 축약하지 않으며 객체 수를 표시하지 않습니다. 자세한 기준과 한계는 [CONTOURS.md](CONTOURS.md)에 있습니다. 프레임 잔상은 제거했습니다.

## 상태·고장 처리

| 상태 | 표시 |
|---|---|
| waiting | 웹 서버는 동작하지만 아직 스캔이 없습니다. |
| live | ROS 소스에서 새 스캔을 수신 중입니다. |
| stale | 서버 마지막 수신에서 1.5초 초과입니다. 점·방향별 거리 표시를 숨깁니다. |
| error | 소스 초기화나 입력 정규화 오류입니다. |
| synthetic | 명시적으로 선택한 합성 서버 소스입니다. |
| replay | 파일 소스입니다. |
| ended | 파일이 끝나 마지막 프레임을 정적으로 표시합니다. |

브라우저 SSE 연결 자체가 끊어지면 별도 연결 끊김 상태입니다. 수신 재개 시 최신 메시지로 복귀합니다. 실패 시 합성 데이터나 과거 센서 기록으로 자동 대체하지 않습니다.

수신률과 stale 판정은 서버의 monotonic clock을 기준으로 합니다. ROS header stamp와 호스트 시계가 같은 기준이라고 가정하지 않습니다. 화면 경과 시간은 서버 수신 이후 시간이며, 기기 내부 지연·네트워크 전송 지연을 정확히 계측한 수치가 아닙니다.

## HTTP 계약

| 경로 | 응답 |
|---|---|
| `/` | 웹 앱 |
| `/api/frame` | 최신 scan 및 입력 상태 JSON |
| `/api/health` | scan 배열을 제외한 상태 JSON. HTTP 200은 센서 정상 보증이 아닙니다. |
| `/api/events?hz=1` | SSE 1 Hz |
| `/api/events?hz=2` | SSE 2 Hz |

스캔 schema는 `smartcart.scan.v1`, envelope는 `smartcart.envelope.v1`입니다. `ranges`의 null은 비유한 입력 자리이며, 배열 인덱스는 유지됩니다. `truncated`, `warnings`, `stats`, `source.kind`, `source.original_kind`로 자료의 완전성과 출처를 전달합니다. 캡처 파일의 `scan` 속성도 재생에서 읽습니다.

SSE 최대 동시 클라이언트는 8개입니다. 별도 전송 큐에 오래된 프레임을 쌓지 않습니다. HTTP 경로는 `web/` 아래 정적 자산으로 제한하고, 상위 경로 이동을 거부합니다. 파일 업로드·파일 삭제·ROS 파라미터 변경·모터 명령 API는 없습니다. 신뢰할 수 있는 LAN 또는 SSH 터널 전용이며 인터넷 공개용 인증·TLS·트래픽 제어 서비스가 아닙니다.

## 전륜 차동구동과 PID

현재 구동계 전제는 사용자가 지정한 전방에 좌우 구동륜이 있는 차동구동입니다. 브라우저 카트 기호에도 앞쪽 좌우 구동륜을 표시합니다. 축간거리·트레드·차체 외곽 실측값은 이 프로그램에 확정값으로 넣지 않았습니다.

**현재 패키지에는 PID 제어기가 없습니다.** `/cmd_vel` 발행, GPIO/PWM 출력, INT-2 구동, UWB 표적 위치 생성도 없습니다. 센서 시각화를 준비하는 단계에서 제어 버튼을 흉내 내거나 가상의 모터 피드백을 표시하지 않습니다.

향후 제어 구조의 권장 분리는 다음과 같습니다.

```text
LiDAR + 실제 UWB -> 추종/충돌 판단 -> 카트 목표 v, ω
                                    │
                            차동구동 역기구학
                                    │
                      좌/우 바퀴 목표 각속도
                                    │
             엔코더 실제 각속도 -> 좌/우 PID -> 드라이버
                                    │
                  독립 하드웨어 정지 / watchdog
```

순수 구름·무미끄럼의 이상화된 운동학에서 바퀴 유효 반지름 `r`, 좌우 접지 중심 간 거리 `b`라면:

```text
ωleft  = (v − ωz · b / 2) / r
ωright = (v + ωz · b / 2) / r
```

이는 제어 명령 생성의 시작 모델이지 실물 정확도 보증이 아닙니다. 바퀴 방향 부호, 실제 유효 반지름·트레드, 모터·감속기·엔코더 사양을 확인해야 합니다. 엔코더나 동등한 속도 피드백 없이 PWM만 내보내는 것을 실제 바퀴 속도 PID가 완성된 것으로 취급하지 않습니다. 이 순수 운동학은 모델 가정에 따른 설계 설명입니다.

뷰어의 1/2 Hz 주기는 사람이 보는 화면용입니다. 향후 모터 속도 폐루프나 비상정지 제어 주기로 사용하지 않습니다. 제어기 주기는 모터·엔코더·버스·측정된 지연에 맞춰 별도 설계해야 하며, 이 패키지는 실시간 제어 성능을 검증하지 않았습니다.

SLAM 또는 카트 이동 중 전역 지도가 필요하면 장착 TF, 시간 동기화, 바퀴 오도메트리/IMU 또는 스캔 정합과 지도 추정 계층이 별도로 필요합니다. 현재 제공하는 것은 최신 스캔의 카트 중심 2D 관측 화면입니다. 참고 이미지의 다층·높이별 3D 점군은 C1의 단일 수평 스캔만으로 같은 형태로 복원하지 않습니다.
