# 첨부 스캔 분석

원본: `samples/user_scan_truncated.txt`. 사용자가 제공한 텍스트를 이름만 바꾸어 그대로 포함했습니다. JSON 버전은 비유한 값을 null로 변환하고 배열 길이·유효성 통계를 붙인 파일입니다. 원본의 생략 구간은 복원하지 않았습니다.

## 실제 값

| 항목 | 첨부 값 / 집계 |
|---|---:|
| frame_id | laser |
| angle_min | −3.1415927410125732 rad |
| angle_max | +3.1415927410125732 rad |
| angle_increment | 0.008738784119486809 rad ≈ 0.500695° |
| scan_time | 0.09972313791513443 s |
| scan_time 역수 | 약 10.027763 Hz |
| range_min | 0.05000000074505806 m |
| range_max | 16.0 m |
| 각도 메타데이터상 예상 길이 | round((angle_max−angle_min)/angle_increment)+1 = 720 |
| 실제 제공 거리 항목 | 128 |
| 뒤에 생략 표시 | `'...'` 존재 |
| 센서 범위 안의 유한 값 | 56 |
| Inf | 40 |
| 센서 최소거리 미만 유한 값 | 32 |
| 센서 최대거리 초과 값 | 0 |
| 제공한 첫 항목~마지막 항목의 각도 폭 | 약 63.588322° |

128개 중 56개는 정의된 유효 거리 안에 있으며, 나머지는 Inf 또는 최소거리 미만입니다. JSON 원본 배열에는 모든 128개 자리와 유한 값이 보존되고, 화면에 유효한 56개만 그립니다. 실제 전송 메시지의 전체 배열 길이는 새로운 완전한 스캔으로 확인해야 합니다. 720은 이 파일의 각도 메타데이터로 계산한 값입니다.

ROS 2 Humble `ros2 topic echo` 소스의 기본 배열 출력 길이는 128이며 `--full-length`로 생략 없이 출력할 수 있습니다. 따라서 이 파일은 기본 CLI 출력 생략과 부합합니다. 근거: [ros2cli Humble echo.py](https://github.com/ros2/ros2cli/blob/humble/ros2topic/ros2topic/verb/echo.py).

## 해석의 한계

이 자료만으로 정상적인 방·복도 전체 형상을 재구성할 수 없습니다. 뒷부분 592개 항목을 추정하거나 선으로 채우지 않습니다. 제공된 매우 짧은 거리값의 원인이 카트 프레임 반사, 손·가림, 장착 환경, 기기 문제 중 무엇인지는 첨부 값만으로 확정할 수 없습니다.

샘플 모드 기본 표시 반경을 5 m에서 0.25 m로 바꾸면 원점 근처의 실제 제공 점들이 확대됩니다. 측정값을 늘리거나 옮기는 기능이 아닙니다. 실물의 장착 방향이 확정되지 않았으므로 화면에서 ‘후방’으로 나오는 점을 실제 카트 후방 물체라고 곧바로 확정할 수 없습니다.

원본은 특정 시점의 한 스캔입니다. 샘플 화면의 회전선이 움직여도 새로운 센서 데이터가 들어오는 것은 아닙니다. 화면에 정적·부분 스캔이라고 명시합니다.

## 재현 명령

```bash
python3 radar.py inspect samples/user_scan_truncated.txt
python3 radar.py serve --mode replay --file samples/user_scan_truncated.json --loop
```

실시간 모드는 이 CLI 출력 텍스트를 읽지 않고 ROS의 `LaserScan.ranges` 배열을 직접 구독합니다. 따라서 CLI의 128개 출력 생략 문제를 경유하지 않습니다.
